# 环境搭建与模型部署

- :one:创建一个新的虚拟环境，python = 3.10

``` bash
conda create -n 环境名 python=3.10   
```

- **:two:激活环境**，然后安装

  `pip install  vllm==0.4.2 transformers==4.46.3 huggingface_hub==0.27.1 trl==0.8.6 accelerate==0.30.1 peft==0.11.1 datasets==2.19.1 `
  
  >  已经验证是兼容的   **注：**vllm启动需要较大的内存！


- :three:下载huggingface中的Qwen 2.5 ，`huggingface-cli download Qwen/Qwen2-7B-Instruct-AWQ --local-dir /root/autodl-tmp/Qwen2-7B-Instruct-AWQ`

- 开机 AutoDL 实例，进入终端，激活预构建 conda 环境

```
conda activate 环境名
```

**​1​.**执行启动脚本`start_vllm_server.sh`，后台拉起 vLLM 服务

**注：**vllm启动需要较大的内存！服务器带卡开机

> \# 给脚本添加执行权限 
>
> chmod +x scripts/start_vllm_server.sh 
>
> 安装tmux   
>
> apt update
>
> apt install -y tmux
>
> 启动vLLM服务   bash start_vllm_server.sh
>
> 看到输出里的公网地址，说明服务已经在 tmux 后台跑起来了

**2.**vLLM 后台启动完成后，使用**本地回环地址**新开终端执行校验命令，确认服务正常：

```bash
curl http://127.0.0.1:6006/v1/models -H "Authorization: Bearer eda-dev-key-2026"
```

返回模型名称即代表服务正常，再执行接口测试脚本。

**3.** 新开终端窗口，运行`api_test_client.py`完成全功能验证

> 把代码中的BASE_URL填写（直接使用本地回环地址 或者 公网访问地址，控制台->自定义服务->查看所租用服务器的公网IP，示例：https://u929078-9659-ea0648dd.bjb1.seetacloud.com:8443）好了之后，运行：
>
> ```
> python api_test_client.py
> ```
>
> 如果能看到模型查询、问答、代码生成的输出，说明公网 API 调用完全正常。
>
> 注：本地回环地址，适用于AutoDL 容器内部访问；公网地址可支持AutoDL 外部本地电脑、其他开发设备远程调用，用于验证对外接口连通性，可提供给前后端开发人员对接使用

**4. 结束本阶段开发之前，建议手动关闭tmux的后台服务**

```bash
tmux kill-session -t vllm-eda
```
